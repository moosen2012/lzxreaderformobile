# 测试指南

> 配套样例数据：`testdata/inbox/`（12 个文件，含 4 层目录、中文路径、公式、代码、Mermaid、非法语法、不支持扩展名）

## 0. 三层策略

| 层 | 手段 | 能发现什么 | 耗时 |
|---|---|---|---|
| 自动 | `npm run verify` | 类型错误、目录树/公式/预处理逻辑回归 | 30s |
| Web 快测 | `npm run web` + 导入 `testdata/inbox` | 布局、点击语义、面包屑、空态、渲染效果（**推荐先跑这层**） | 5min |
| 真机 | Expo Go（Android） | 抽屉手感、物理返回键、SAF 目录授权、滚动性能 | 20min |

**平台能力差异必须先知道**：

| 能力 | Web | Android | iOS |
|---|---|---|---|
| 导入整个目录 | ✅ `<input webkitdirectory>` | ✅ SAF | ❌ 会提示"当前平台不支持导入整个目录" |
| 添加单个文件 | ✅ | ✅ | ✅ |
| 树形结构 | ✅ | ✅ | 只能测单文件（无目录 → 侧栏只有一个根节点） |
| 物理返回键 | — | ✅ | — |

所以**侧栏 / 树 / 面包屑只能在 Web 或 Android 上验**，iOS 无法覆盖。

## 6. 常见故障

| 现象 | 原因 / 处理 |
|---|---|
| 启动报 `Cannot find module 'mathjax-full'` | 没装新依赖，`npm install` |
| 改了代码但页面没变 | `npx expo start --clear` |
| 公式显示成红色 `Unknown environment 'pmatrix'` | 宏包配置模块没被引入（应有显式 import，见 `src/utils/mathRenderer.ts`） |
| Web 导入目录后刷新文件没了 | 内容存 localStorage，超配额会被丢；换小目录测 |
| Web 端目录选择器点不动 | 浏览器不支持 `webkitdirectory`，换 Chrome/Edge |
| 启动即弹 `Expo Go isn't responding` | 冷启动被大模块拖住。检查 `mathjax-full` 是否只在 `mathjaxEngine.ts` 里被 import（不能有别的文件直接 import mathjax）；再 `npx expo start --clear` |
| 公式一律显示成 TeX 源码 | 引擎加载失败。检查 `import('./mathjaxEngine')` 是否被改坏，或 bundle 里是否漏了 mathjax |
| 顶部标题被状态栏压住 | `HomeScreen` 未消费 `useSafeAreaInsets`；确认 `AppHeader` 的 `paddingTop: insets.top` 还在 |
| 树里点文件没反应 | 检查是否点到了箭头热区（箭头只做折叠） |

## 7. 已知限制（不算 bug，别当问题提）

1. **空目录不显示**：`FileItem.directory` 只是相对路径字符串，没有目录句柄，没文件就没节点。
2. **不支持新建/移动文件夹**：同上，属独立需求（需加 `folders: string[]`）。
3. **iOS 不支持导入整个目录**：SAF 仅 Android 有实现。
4. **Mermaid 依赖 WebView + CDN**：离线环境下会显示渲染失败兜底。
5. **公式出现在标题/表格单元格**：inline view 嵌在 `<Text>` 里仍有边缘问题，正文段落已解决。
6. **首次打开含公式的文件会慢一拍**：mathjax 引擎是延迟加载的（为了不拖慢冷启动），第一次渲染公式要等它加载，期间显示 TeX 源码；之后走缓存。
